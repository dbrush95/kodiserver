Guide

Pluto, Samsung TV Plus, Plex, Roku, Tubi, and the Ohio stations refresh here. WHIO is the Cox public stream. Philo, Hulu, Disney+, and Paramount+ stay signed in through SlyGuy on the Shield. Set IPTV Merge’s output to the KodiPlaylists share so that guide is included. Kodi should use the Tvheadend client and leave IPTV Simple off, which is what cuts the startup and buffer time.

Connect once, play everywhere

  1. Add compatible M3U sources in Tvheadend → Configuration → DVB Inputs → Networks → IPTV Automatic Network. Set the provider’s maximum concurrent streams.
  2. Scan/map the working channels and configure an XMLTV guide grabber and its update schedule. A playlist alone does not provide guide data.
  3. Choose a recording location in Configuration → Recording → Digital Video Recorder Profiles. Prefer a mounted external drive; the Tvheadend service account needs write permission.
  4. On Kodi, enable Tvheadend HTSP Client. Set the Pi address, HTTP port 9981, HTSP port 9982, and that client’s Tvheadend user/password.
  5. Test live playback, guide updates and one scheduled recording before disabling duplicate channels from IPTV Simple.
Direct HTTP entries are candidates, not guaranteed playable sources. Kodi plugin URLs, DRM properties and local proxies still need investigation. Streaming subscription logins are not shared automatically.

SET UP A NEW DEVICE

One connection. A familiar home.

  1. Install the same Kodi major version.
  2. Add an SMB network location for the Pi. Use the Samba account created by the installer.
  3. From KodiClients, install service.kodiserver.client-0.2.0.zip.
  4. Open Kodi Server Companion and choose profile.json in that share.
  5. Use its setup menu to install the packaged repositories, then required add-ons, then apply the shared profile.
  6. Enter the client’s TV and streaming-service logins. Repeat enrollment for each Kodi user profile that should follow the server.

“Apply shared profile” opts this device into later skin/weather changes. Local audio, remote controls, service logins and databases are preserved.

Capture your preferred layout

First configure the skin and weather on the Shield. Make an uncompressed Kodi backup, import it here, then capture the selected profile. This packages repository ZIPs and the selected skin/weather settings; it does not mirror all add-on data or credentials.

Skin-specific helper files, local artwork paths and third-party widget dependencies may need separate migration. Test the profile on one client before enrolling the rest.

Metadata & faster startup

Tvheadend owns the supported channels, EPG and recordings. An optional MariaDB library shares Kodi’s native movie/show metadata and watched status; it does not share streaming add-on catalogs.

Run bash setup-server.sh library to prepare MariaDB. After installing the companion, use its shared-library setup. Keep all clients on the same Kodi version and media sources reachable at identical network paths.

Use one companion’s “Scan shared library” option for periodic scans. Configure that client’s media sources first. Kodi still performs the scans; MariaDB stores the results on the Pi. Do not expect the Pi database to scrape your media by itself.

Keep artwork caches on each client. Reduce startup widgets, disable unused add-on services, and measure startup before/after. Central storage cannot remove local add-on authentication or widget work.

START HERE

Shield backup → Pi → another Kodi device

1. Create the Shield backup

In Kodi: Settings → Add-ons → Install from repository → Kodi Add-on repository → Program add-ons → Backup. Install the add-on by robweber.

In Kodi’s file manager, add smb://dallas@192.168.1.119/KodiBackups. Use the Pi passphrase as the Samba password. In Backup → Remote Directories, choose that source. In File Selection, enable User Addons, Addon Data, Config Files, Database, Playlist, Profiles (if used), and Thumbnails/Fanart. Leave compression off for the first backup.

Run Backup. When it completes, open Restore only to verify that a newly dated backup appears; cancel without restoring.

2. Store the backup on the Pi

The dated folder lands in the KodiBackups share. After it stops changing, this Pi copies it into the recovery library. Keep a second copy on your computer. A USB import still works if you mount the drive and enter its dated-folder path.

3. Prepare a compatible client

Install the same Kodi major version and Backup add-on on the target device. Copy the stored backup’s dated folder/ZIP into a dedicated backup destination accessible to that device, preserving its contents and filename. Point Backup at the parent folder, select Restore, and choose the restore point.

A full restore is best used on the original Shield. For Firesticks, check Android and processor compatibility; native add-ons may need reinstalling. Start with selected settings, then verify playback, skin widgets, audio, and remote controls. Some services require signing in again.

4. Distribute changes deliberately

Make a fresh backup after changing your main Kodi setup. Import it with a clear version label, test it on one spare client, and only then restore the compatible selections to other devices. Do not replace each device’s complete settings automatically.

The Pi stores your Android backups; it does not run those backups as its own Kodi installation. Linux, Android, and tvOS setups are not interchangeable.
